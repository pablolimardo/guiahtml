🧑‍🏫 Plan de clase para el docente

Propósito: que cada grupo construya la web de su proyecto de Expotécnica con estructura semántica, diseño responsivo y una interacción en JavaScript. Retoma y consolida contenidos de Informática Aplicada.

Duración sugerida: 2 clases de taller. Ajustable según el avance de cada grupo.

  1. Clase 1 · Estructura y diseño. Gancho con el tablero de capas (10'). Misiones 0 a 3 en el pizarrón y en la compu (60'). Misiones 4 y 5 (40'). Cierre: 3 palabras nuevas al glosario personal.
  2. Clase 2 · Responsive y cerebro. Misión 6 con el simulador y el modo dispositivo del navegador (35'). Misión 7 comparando JS con Python (35'). Misión 8: cada grupo adapta la plantilla con los datos reales de su proyecto (60'). Prueba final en el celular de un compañero.

Recursos: VS Code con la extensión Live Server. Si no hay instalación, alcanza con cualquier editor de texto y el navegador. El Laboratorio de esta guía necesita internet solo para abrir la página.

Evidencia de aprendizaje: la carpeta del sitio y el checklist "Web lista para la Expo" del cierre, que puede usarse como criterio de la rúbrica del proyecto.

Articulación: fotos y diagramas del prototipo con Tecnología y Control; la lógica del panel se conecta con lo trabajado en Python y pyFirmata.

M1

El esqueleto de toda página

≈ 15 min · HTML

HTML trabaja con etiquetas. Una etiqueta abre <p>, envuelve contenido y cierra </p>. Como una caja con tapa.

Toda página arranca con el mismo esqueleto. Lo escribís una vez y lo reutilizás siempre, como el programa base del Arduino con setup() y loop().

💡 Atajo de VS CodeEn un archivo .html vacío escribí ! y apretá Tab. Te arma el esqueleto solo. Después cambiá lang="en" por lang="es".
🎯 Mini-desafíoPegá el esqueleto en tu index.html, cambiá el título por el nombre de tu proyecto y abrilo con Live Server. Si ves tu h1, ¡primera misión técnica superada!

📥 Kit de imágenes del proyecto

Te dejamos imágenes de referencia listas para usar en la plantilla. Descargalas y guardalas en tu carpeta img.

Qué trae el kit y dónde va cada una:
  • tanque.png → la portada (hero)
  • sistema.png → la sección "Cómo funciona"
  • sensor.png → la sección "Materiales"
  • esquema.jpg → el esquema de conexiones
📥 Descargar el kit desde Drive

Cómo bajarlas todas juntas: en Drive, seleccioná todas las imágenes con Ctrl + A → clic derecho → Descargar. Te baja un .zip: descomprimilo y mové las imágenes a proyecto-expo/img.

⚠️ Trampa de las extensionesAlgunos archivos pueden venir como sensor.jpg.png. La extensión real es la última (.png). Renombralos a sensor.png, tanque.png y sistema.png. En Windows activá Vista → Mostrar → Extensiones de nombre de archivo para ver el nombre completo. Es el mismo cuidado que con un .py que se guardó como .py.txt.

La etiqueta <img> a fondo

🧩 Analogía<img> no "contiene" la imagen: es un cartel que dice dónde buscarla. Como en el código de Arduino cuando ponés el número de pin: el sensor no está en el código, el código dice dónde está conectado.
AtributoQué haceSi lo olvidás…
srcLa ruta al archivo: dónde está la imagen.Aparece el ícono de imagen rota.
altDescribe la imagen con palabras. Lo lee un lector de pantalla y aparece si la imagen no carga.Tu web deja afuera a personas con discapacidad visual y Google no entiende la imagen.
width y heightLe avisan al navegador la proporción, para que reserve el lugar antes de cargar.La página "salta" mientras carga, sobre todo en el celu.
loading="lazy"Carga la imagen recién cuando te acercás scrolleando.El celu descarga todo de una y tarda más. En la portada no lo uses: esa tiene que aparecer ya.
💡 ¿Cómo sé el ancho y el alto?Clic derecho sobre el archivo → Propiedades → Detalles. O abrila en el navegador y mirá la pestaña. No tiene que ser exacto: lo que importa es la proporción. El CSS después la adapta a la pantalla.
💡 Un buen altDescribí lo que se ve y por qué importa. alt="imagen1" ❌ · alt="foto" ❌ · alt="Sensor ultrasónico HC-SR04 con sus cuatro pines de conexión" ✅

Rutas: la dirección de la imagen

La ruta se lee desde donde está el archivo que la usa. Es como darle indicaciones a alguien parado en tu index.html.

Imagen con epígrafe: <figure>

Para esquemas y diagramas, envolvé la imagen en <figure> y agregá un <figcaption>: el texto que la explica debajo, como en un libro técnico.

Y en el CSS, tres reglas que toda imagen necesita:

🧩 object-fit: coverEs como poner una foto en un portarretratos: si no entra justa, se recorta un poco el borde, pero nunca queda estirada ni aplastada.
⚠️ Error clásicoLa foto no aparece. Casi siempre es la ruta: fijate que el nombre en src sea idéntico al del archivo, mayúsculas incluidas.
🎯 Mini-desafío
  1. Descargá el kit, renombrá los archivos y guardalos en img.
  2. Poné tanque.png en la portada con un alt escrito por vos (sin loading="lazy").
  3. Agregá esquema.jpg dentro de un <figure> con su <figcaption>.
  4. Completá la sección "problema" con tu problema real en 2 o 3 oraciones y la lista de materiales.
  5. Prueba de fuego: cambiá a propósito una letra del src. ¿Qué se ve? ¿Aparece tu alt? Después arreglalo.
M4

Pintá el tablero con CSS

≈ 20 min · CSS

Una regla CSS tiene tres partes: a quién (selector), qué cambio (propiedad) y cuánto (valor).

El truco profesional: variables

Si repetís #00c8ff en 30 lugares y querés cambiar el color, tenés 30 cambios. Con una variable, cambiás una sola línea. Es como una constante en Python.

💡 Paleta rápidaElegí un color de acento que tenga que ver con tu proyecto: celeste para agua, verde para invernadero, naranja para energía solar. Menos es más.
🎯 Mini-desafíoCreá tus variables en :root con la paleta de tu proyecto. Hacé un botón con class="boton" y probá cambiar solo --acento: mirá cómo cambia todo junto.

Los 4 trucos que lo hacen posible

Truco 1 · Imágenes que no se escapan. Una foto de 4000 px nunca debe romper la pantalla del celu.

Truco 2 · Letra fluida con clamp(). Le das un mínimo, un ideal y un máximo. Como un termostato: nunca baja ni sube de los límites.

Truco 3 · La grilla mágica. Una sola línea y las tarjetas se reacomodan solas: 3 por fila en la compu, 1 en el celu. Sin media queries.

Truco 4 · Consultas de tamaño. Con @media preguntás por el ancho de la pantalla. Con @container, por el ancho de una caja: la tarjeta decide sola cómo acomodarse.

💡 Probá en el celu sin tener celuF12 → ícono de celular/tablet (o Ctrl + Shift + M). Elegí "iPhone" o "Galaxy" y mirá tu página como la verá el jurado.
🎯 Mini-desafío
  1. Aplicá los 4 trucos a tu página.
  2. Poné las 3 partes de tu sistema (sensor, control, actuador) en una .grilla.
  3. Probala en modo dispositivo a 360 px. Si no aparece barra de scroll horizontal, ¡superado!

Glosario + checklist para la Expo

¡Muy buen trabajo! Pasaron de una página en blanco a una web responsiva con un panel interactivo. Sumá estas palabras a tu glosario técnico personal.

Etiqueta
Instrucción de HTML que envuelve contenido: <p>...</p>.
HTML semántico
Usar etiquetas con significado: header, main, section, footer.
Selector
La parte de CSS que dice a qué elementos se aplica una regla.
Variable CSS
Un valor con nombre (--acento) que se reutiliza en toda la hoja.
Modelo de caja
Contenido + padding + border + margin.
Responsive
Diseño que se adapta a cualquier tamaño de pantalla.
Mobile first
Diseñar primero para el celular y después ampliar.
Media / container query
Reglas que se activan según el ancho de la pantalla o de una caja.
DOM
El "mapa" de la página que JavaScript puede leer y modificar.
Evento
Algo que pasa (un clic, mover un deslizador) y dispara una reacción.
